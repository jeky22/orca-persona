# Orca Persona

경로 묶음(페르소나)별로 깃 아이디, Claude/Codex 계정, 지시문이 따라오게 하는 Orca 플러그인 (`trusted-worker`).

> 상태: Orca **1.4.254에서 실기 검증 전 항목 완료** (2026-11-09). 실행 훅·포커스 전환·계정 선택·`system` 해제·지시문 마커 교체·깃 아이디·타임아웃 거부·**resume**을 실제 Orca에서 확인했고, 실기에서만 드러나는 버그 2건(훅 workspaceId 형식, 로컬 hostId)을 고쳤다. **보기 전용 Persona 패널**(그룹 뷰) 포함, 단위 테스트 121개. 남은 미확인은 로그인 만료 응답 형태뿐 — "알려진 한계" 참고.

## 요구 사항

- Orca **1.4.248 이상** (훅이 그 버전부터)
- Claude / Codex CLI
- 페르소나가 쓸 계정을 Orca에 등록: 페르소나 수만큼
  ```
  orca account add --agent claude
  orca account add --agent codex
  ```

## 설치 (개발 로드)

```
orca plugin dev load .
orca plugin dev load . --approve <출력된 fingerprint>
orca plugin list          # orca-persona 가 enabled 인지 확인
```

## 페르소나 파일

위치는 `~/.orca/personas/*.md`. 플러그인 설정 `personasDir`로 바꿀 수 있다 (`~` 허용, 비워 두면 기본값). **파일명(확장자 제외)이 페르소나 이름**이다. 파일이 하나도 없으면 아무것도 하지 않는다.

`~/.orca/personas/work.md`:

```markdown
---
match:
  - ~/workspace/**
git:
  name: Jechan Lee
  email: jechan.lee@gwanaklab.co.kr
accounts:
  claude: jechan.lee@gwanaklab.co.kr   # orca account add 로 등록한 계정의 이메일
  codex: jechan.lee@gwanaklab.co.kr
---

사내 코드베이스다. 커밋 메시지는 한국어로 쓴다.
PR 본문에 Jira 키를 반드시 넣는다.
```

### 문법

파서는 아래만 받는다. 그 밖의 것은 파싱 오류이며, 오류가 난 파일은 로그를 남기고 무시된다.

| 항목 | 규칙 |
|---|---|
| frontmatter | 첫 줄이 `---`, 닫는 `---` 줄이 있어야 한다. 그 아래 전부가 지시문 본문 |
| 최상위 키 | `match:`, `git:`, `accounts:` 만 (줄 끝에 값 없이 `키:`). 다른 키는 오류 |
| `match` | 필수, 1개 이상. 항목은 들여쓴 `  - <glob>` 형태 |
| `git` | 들여쓴 `  name: ...`, `  email: ...`. 둘 다 필요 |
| `accounts` | 들여쓴 `  claude: <이메일>`, `  codex: <이메일>`. 값은 비어 있으면 안 됨. 이메일 대신 `system`이라고 쓰면 관리 계정 선택 해제(시스템 기본 계정). 키를 빼면 그 에이전트 계정은 건드리지 않음. `git`이 있으면 `accounts:` 아래가 비어 있거나 섹션 자체가 없어도 됨 |
| 들여쓰기 | 공백 2칸 이상 |
| 주석 | `#`로 시작하는 줄, 값 뒤의 ` # 설명` |
| 따옴표 | 값과 glob에 `"..."` 또는 `'...'` 사용 가능 (따옴표 안의 `#`은 주석 아님) |
| 최소 조건 | `git`과 `accounts`가 모두 없으면 오류 |

소속 판정은 `match` glob을 워크스페이스 경로에 맞춰서 한다. glob 규칙:

- `~`는 홈 디렉터리로 확장된다 (`~` 단독 또는 `~/...`).
- `*`는 `/`를 넘지 않는 0글자 이상, `?`는 `/`가 아닌 한 글자.
- `**`는 `/`를 넘는다. 끝의 `/**`는 기준 디렉터리 자체도 맞춘다 (`~/workspace/**`는 `~/workspace`도 포함).
- 대소문자를 구분한다 (Windows 드라이브 문자만 예외).
- 역슬래시(`\`)는 `/`로 바꿔서 비교한다. 끝의 `/`는 무시한다.
- `{a,b}`, `[abc]`는 지원하지 않는다 (글자 그대로 비교).
- 세그먼트 안에 붙은 `**`(예: `~/work**`)는 `.*`처럼 동작해 `/`를 넘는다. 의도와 다를 수 있으니 쓰지 말고 `~/work*/**`처럼 나눠 쓴다.

판정 규칙:

- 여러 페르소나가 맞으면 **가장 긴 패턴**이 이긴다. 길이는 `~`를 확장한 패턴 문자열의 글자 수다. 동률이면 아무것도 하지 않고 로그만 남긴다.
- 경로는 먼저 받은 그대로 맞춰 보고, 아무것도 안 맞으면 심볼릭 링크를 푼 실제 경로(realpath)로 다시 맞춘다.
- 레포별 예외: 레포 루트의 `.orca-persona` 파일 첫 줄에 페르소나 이름을 적으면 경로 규칙보다 우선한다. 그 이름의 페르소나가 없으면 로그를 남기고 경로 규칙을 쓴다.
- 원격 호스트 워크스페이스는 손대지 않는다.

## 동작 세 경로

| 훅/이벤트 | 하는 일 |
|---|---|
| `workspace.create.after` (훅) | 페르소나를 찾아 `git config --local user.name/user.email`을 기록한다. 레포에 이미 `user.email`이 있으면 건너뛴다 |
| `agent.launch.before` (훅) | 워크스페이스 id로 경로를 풀어 페르소나를 찾고, 지시문 구간을 교체한 뒤 Orca에 계정 선택을 요청하고 통과시킨다. 계정은 매번 새로 읽은 목록으로 판단하며, 이미 활성이면 요청하지 않는다. 페르소나에 실행하는 에이전트의 계정 키가 없으면 지시문만 교체하고 통과한다. 전체를 **1.7초 기한** 안에 끝내야 한다 (Orca 훅 예산 2초).<br>**그대로 통과**: `workspaceId`가 null(플로팅 터미널) / claude·codex가 아닌 에이전트 / 워크스페이스 id를 찾지 못함 / 원격 호스트 워크스페이스 / 페르소나 없음.<br>**실행 거부**: 페르소나의 이메일이 Orca에 등록돼 있지 않음 / 로그인 만료 / 같은 이메일 계정이 둘 이상 / Orca 런타임 RPC 불가·오류 / 워크스페이스 목록 조회 실패 / 지시문 파일 쓰기 실패 / 1.7초 기한 초과 |
| `workspace.changed` (이벤트) | 포커스된 워크스페이스를 이름+브랜치로 `workspace.list`에서 찾아 페르소나를 적용(지시문 + 계정)한다. 적용 중에 들어온 포커스 이벤트는 마지막 하나만 남겼다가 이어서 적용한다. 실패해도 거부할 대상이 없으므로 로그를 남기고 상태바에 `persona: <이름> ⚠`를 띄운다 |

`agent.launch.before`가 정확한 경로이고(workspaceId가 있음), `workspace.changed`는 포커스를 따라가는 경로다. 계정 선택은 호스트 전역이므로 "마지막으로 누른/띄운 프로젝트"가 계정과 지시문을 함께 끌고 다닌다. 이미 돌고 있는 세션에는 영향이 없다.

상태바는 `persona: <현재 페르소나>` (적용 전에는 `persona: —`)이고, 클릭하면 `persona.status`가 실행된다.

## 지시문

페르소나 본문은 전역 `~/.claude/CLAUDE.md`와 `~/.codex/AGENTS.md`의 마커 구간으로 들어간다.

```
(사용자 내용 그대로)
<!-- orca-persona:begin work -->
사내 코드베이스다. ...
<!-- orca-persona:end -->
```

- 마커 구간만 교체하고 나머지는 보존한다. 파일이 없으면 만들고, 마커가 없으면 끝에 붙인다.
- 본문이 비어 있으면 구간을 제거한다.
- Orca가 모든 관리 계정 홈에서 전역 파일을 가져다 쓰기 때문에 전역 파일을 쓴다.
- 교체 시점은 계정 선택 직전이다 (포커스 경로와 실행 경로 모두).

## 패널 (보기 전용)

우측 사이드바에 **Persona 패널**이 생긴다 (활동 바의 layers 아이콘, `orca plugin open local.orca-persona`로도 열림).

- **현재 상태**: 적용된 페르소나, 포커스된 워크스페이스, Claude/Codex 활성 계정. 마지막 적용이 실패했으면 사유를 경고로 보여준다.
- **그룹 뷰**: 페르소나별 카드에 match 글롭, 깃 아이디·계정 배지, 그리고 **그 페르소나에 매칭되는 워크스페이스 목록**. 어디에도 안 걸리는 워크스페이스는 "페르소나 없음", 원격은 "원격" 카드로 분리된다.
- **파싱 오류**: 무시된 페르소나 파일과 그 이유.
- 포커스가 바뀌거나 페르소나가 적용될 때마다 저절로 갱신된다.

편집은 아직 파일로 한다 (패널은 보기 전용). 페르소나 파일 경로가 패널 하단에 나온다.

## 커맨드

- `persona.applyGit`: 이미 존재하는 워크스페이스에 깃 아이디를 일괄 적용한다. 이미 설정된 레포는 건너뛴다. 계정은 대상이 아니다. 결과는 한 줄로 나온다.
  ```
  applied 3, skipped 1, no persona 4, remote 0
  ```
  (목록이 잘렸으면 끝에 ` (truncated)`, 조회 자체가 실패하면 `failed: <이유>`)
- `persona.status`: `persona: <이름>` 또는 `persona: —`

## 실패 시 메시지 뜻

`agent.launch.before` 거부 이유와 로그에 나오는 메시지다.

| 메시지 | 상황 | 해결 |
|---|---|---|
| `<agent> 계정 <이메일>이(가) Orca에 등록돼 있지 않습니다. orca account add --agent <agent> 로 등록하세요.` | 페르소나 파일의 이메일이 Orca 계정 목록에 없음 (오타 포함) | 안내된 명령으로 계정을 등록하거나 파일의 이메일을 고친다 |
| `<agent> 계정 <이메일>의 로그인이 만료됐습니다. Orca 설정에서 다시 로그인하세요.` | 등록은 돼 있으나 로그인이 만료됨 | Orca 설정에서 다시 로그인 |
| `<agent> 계정 <이메일>이(가) Orca에 둘 이상 등록돼 있어(<id, id, ...>) 고를 수 없습니다. 페르소나에 계정을 하나만 남기거나 Orca에서 중복 계정을 정리하세요.` | 대소문자·공백을 무시하면 같은 이메일인 계정이 Orca에 여러 개 | Orca에서 중복 계정을 지운다 |
| `페르소나 적용이 1.7초 안에 끝나지 않아 실행을 거부했습니다 (Orca 런타임이 느리거나 응답하지 않음).` | 워크스페이스 조회·지시문 쓰기·계정 RPC를 합쳐 1.7초를 넘김 | 다시 실행해 본다. 계속되면 `orca plugin logs orca-persona` 확인 |
| `Orca 런타임에 연결할 수 없어 계정을 바꾸지 못했습니다 (orca account select를 쓸 수 없음).` | 사용자 데이터 경로의 런타임 소켓에 붙지 못함 (Orca 미실행, 사설 프로토콜 변경 등) | Orca가 떠 있는지 확인. 계속되면 이슈로 보고 |
| `Orca 계정 선택 요청이 실패했습니다 (<코드>): <메시지>` | 소켓에는 붙었으나 Orca가 요청을 오류로 응답 | 코드와 메시지를 확인. `orca plugin logs orca-persona` 참고 |

## 알려진 한계

2026-11-09, Orca 1.4.254 (macOS) 실기 검증 기준.

- **포커스 경로는 이름+브랜치로 워크스페이스를 찾는다.** 같은 이름+브랜치가 둘 이상이거나 원격이면 무시한다 (실행 경로는 workspaceId로 정확히 찾으므로 영향 없음). **실사용 영향(실측): 여러 레포를 메인 워크트리 그대로 쓰면 전부 displayName "main"+브랜치 "main"이라 셋 이상 겹쳐, 메인 워크트리 클릭으로는 전환이 일어나지 않는다.** 이름이 고유한 워크트리에서는 정상 동작한다. (`workspace.changed`의 `displayName`·`branch`는 `workspace.list`의 `name`·`branch`와 같은 값·같은 형식이다 — 워크트리 포함 실측, 브랜치는 양쪽 다 `refs/heads/` 없는 bare 이름.)
- 전역 지시문 교체는 Orca 밖에서 띄운 `claude`/`codex`에도 보인다.
- **resume은 훅을 타지 않고, resume 시점의 전역 선택 계정을 쓴다** (1.4.254 실측 + 소스). 그래서 포커스 경로가 덮는 설계가 성립한다: 회사 세션을 닫고 개인 → 회사를 클릭한 뒤 resume하면 회사 계정으로 복원되는 것을 실측했다. 메커니즘: Orca 터미널의 `claude`는 셸 함수 래퍼로 실행 시점마다 선택 포인터 파일(`claude-profiles/selected-host`)을 읽어 홈을 정하고, UI 쪽 세션 재개(`agentSession.create + resumeFrom`)도 현재 선택으로 계정 홈을 리졸브하며 원본 트랜스크립트를 호스트가 임포트한다. 주의: 메인 워크트리 이름이 겹치는 경우(위) resume 직전의 포커스 클릭이 전환을 일으키지 않으므로, 그때는 **마지막으로 적용된 페르소나의 계정**으로 resume된다.
- **훅이 2초를 넘기면 Orca는 `onError: "deny"`가 선언된 훅만 거부하고, 아니면 건너뛰고 통과시킨다** (소스 `runPluginHookChain` + 실측: 3초 지연 시 2.0초에 거부). 이 플러그인은 `agent.launch.before`에 `onError: "deny"`를 선언했고, 그 전에 **1.7초에 스스로 명확한 사유로 거부**한다 (실측: 1.8초 지연 시 플러그인 메시지로 거부).
- 계정 선택은 Orca의 사설 런타임 소켓 RPC(`accounts.selectClaude`/`selectCodex`)를 쓴다. 깨지면 실행을 통과시키지 않고 거부한다. **1.4.254부터 `orca account select --agent claude|codex` CLI가 생겨** 그쪽으로 교체할 수 있다 (아직 RPC 유지 — 검증된 경로이고 CLI는 호출마다 프로세스 스폰 비용이 있다).
- `accounts.list`의 `needsSignIn` 필드는 정상 로그인 계정 응답에는 없다 (코드에선 선택 필드). 로그인 만료 시의 실제 응답 형태는 미확인이다.
- 메인 워크트리가 아닌 워크트리는 `~/orca/workspaces/<레포>/<이름>` 아래 생기므로, 레포 경로(`~/workspace/**` 등)만 match에 적으면 워크트리가 안 덮인다. 워크트리 경로도 함께 적어야 한다.
